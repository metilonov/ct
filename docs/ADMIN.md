# Административная сборка 0.3.0 — 30.10.2026

По запросу владельца это приложение одного администратора без тарифных квот. Общий backend уже защищён ADMIN_API_TOKEN и не имеет публичной регистрации. Дизайн 0.2.0 сохранён; строка подписки заменена профилем Admin без кнопок покупки.

## Снятые ограничения

- Ограничение Free 20 ГБ / Premium 500 ГБ на выбранные файлы.
- Тарифное ограничение 1 / 5 задач в общей очереди.
- Требование Premium для передачи готовых файлов на Android, в том числе автоматической.
- Внутренней квоты приложения на объём назначения Google Drive нет.

GET /account/limits возвращает admin_mode=true, tasks=null, selected_bytes=null, drive_destination_bytes=null, phone_downloads=true. null означает отсутствие продуктовой квоты, а не вымышленную огромную ёмкость. Android читает эти права с сервера. Подмена кнопки или клиентский обход серверной проверки не используются.

ADMIN_MODE включён по умолчанию: уже заданный ACCOUNT_PLAN=free больше не ограничивает администратора. Явный ADMIN_MODE=false сохраняет прежнюю серверную модель для совместимости; это не режим данной Android-сборки. Авторизация, HTTPS, SSRF-защита, rate limiting и контроль свободного диска остаются.

## Что надо сделать на BotHost

Обновить проект из репозитория metilonov/ct и пересобрать Docker-образ/проект, затем запустить новый контейнер с прежними переменными и /app/data. Одной установки APK недостаточно: прежние квоты проверял сервер. При необходимости явно задать ADMIN_MODE=true. OAuth, ключи шифрования и ADMIN_API_TOKEN менять не нужно.

После обновления /health должен показывать version=0.3.0, а подключённое Android-приложение — профиль Admin. Без обновления backend приложение покажет указание обновить сервер и сохранит фактические права старого API.

## Физические ограничения не являются тарифом

MAX_WORKSPACE_BYTES по-прежнему конфигурируется, по умолчанию 10737418240 (10 ГиБ). Расчёт дополнительно ограничен свободным диском BotHost, FS/piece-резервом и техническим запасом. Google Drive — место назначения; это не рабочий диск libtorrent.

Торрент с большим общим размером может обрабатываться пакетами подходящих файлов. Одиночный файл больше вместимости одного пакета по-прежнему НЕ скачивается: bounded streaming не реализован. API не отклоняет его метаданные/создание по коммерческой квоте, но scheduler честно сообщает workspace_or_single_file_limit. В Android эта причина теперь объясняется текстом о рабочем диске, а не о тарифе. Гарантия скачивания одиночного файла любого размера не заявляется.

При наличии большего реального постоянного диска оператор может увеличить MAX_WORKSPACE_BYTES; statvfs и резерв продолжат ограничивать расход. Завышение переменной не создаёт свободное место. Расширение буферизованного потокового режима описано в LARGE-FILE-DESIGN.md и в этой версии не выдаётся за готовую функцию.

Внешние квоты/ошибки самого Google Drive, хостинга и сети приложение отменить не может. Одновременно работает один пакет, число задач в очереди тарифом не ограничивается.

## Проверки

- 21 backend-тест прошёл: нет квот даже при ACCOUNT_PLAN=free, админ-режим включён по умолчанию, phone downloads разрешены. Legacy free-квота проверена только при явном ADMIN_MODE=false.
- Тест прямой HTTPS .torrent-ссылки использует контролируемый ответ URL importer и настоящие libtorrent-метаданные: восемь задач по 150 ГБ созданы без 403/task_limit. Это тест допуска метаданных/очереди, не передача восьми файлов по 150 ГБ.
- Настоящий localhost Uvicorn: health 0.3.0, 401 без авторизации, status/storage/tasks. Это не проверка развёртывания в пользовательском BotHost.
- Debug APK собран, Lint проверен, zip entry contents после перепаковки сохранены, подпись проверена. Сертификат совпадает с предыдущим APK, versionCode=3.
- Нового device/end-to-end прогона этой сборки нет; ранее зафиксированные проблемы эмулятора и незавершённая визуальная приёмка остаются в REDESIGN.md.
