# BotHost Pro: подготовка, не отчёт о выполненном развёртывании

Официальный хост подтверждён пользователем: https://bothost.ru. Доступа к его панели, репозиторию и приложению в этой сессии нет. Платные ресурсы не создавались.

Проверенные публичные источники 2026-10-29:
- https://bothost.ru/docs/domains-and-ports — HTTPS reverse proxy, домен, PORT, bind 0.0.0.0.
- https://bothost.ru/docs/custom-dockerfile — собственный Dockerfile, /app может быть перекрыт исходниками.
- https://bothost.ru/docs/database-storage — /app/data для сохранения БД.
- https://bothost.ru/docs/bot-memory-timeout-rate-limits — ограничения ресурсов; фактические параметры Pro надо смотреть в панели.

Откройте официальный сайт и войдите самостоятельно. Не отправляйте пароль или секреты в чат. В панели проверьте:
1. Доступен ли собственный Dockerfile, HTTPS-домен и PORT=8000.
2. Дисковая квота и постоянное хранилище /app/data, реальный statvfs и рестарт/редеплой.
3. Разрешён ли BitTorrent условиями тарифа, исходящие TCP/UDP и DHT; доступный RAM и CPU.
4. Таймаут reverse proxy: magnet metadata до 60 секунд. При меньшем таймауте нужен асинхронный endpoint метаданных (пока не реализован).
5. Не блокирует ли провайдер libtorrent wheel и native библиотеки.

Конфигурация: загрузить архив или Git-проект, выбрать корневой Dockerfile. Включить домен, внутренний порт 8000; переменные из .env.example задать через панель. Ключи не добавлять в Git. DATA_DIR=/app/data, один процесс Uvicorn. Код образа находится вне /app, чтобы mount исходников не скрыл его.

Проверка после запуска: /health, авторизованный /server/status, /server/storage. Android принимает HTTPS URL именно этого приложения и ADMIN_API_TOKEN, а не пароль/ключ панели BotHost. Drive подключается отдельно.

Если на Pro нет необходимого диска или BitTorrent запрещён: не обходить ограничения. Вариант — один backend/движок на уже имеющемся подходящем сервере, BotHost-бот остаётся API-клиентом. Если недоступен только публичный HTTPS, возможен поддерживаемый провайдером исходящий tunnel с TLS, с проверкой условий. Новые платные ресурсы требуют согласования.

Нельзя считать этот Dockerfile проверенным на BotHost до реального деплоя. Дисковый бюджет меньше min(10 ГиБ, свободное место минус технический резерв). Желательна отдельная файловая квота/volume на уровне хоста: statvfs не отражает все ограничения hosting quota.
